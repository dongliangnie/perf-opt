ARM 优化阶段 1：GCC -O2 编译器优化

一、阶段定位

本阶段在 ARM 优化基准版本基础上进行第一个 ARM 平台优化。
本阶段不修改任何 C 源码，只改变编译选项：

    -O0 -> -O2

对应 ARM 平台优化表第 1 行：
    优化前：370.698124 ms
    优化后：89.478562 ms
    加速：75.86%
    final_sum：33407.632487

三、本阶段做了什么优化

本阶段只改变编译命令中的优化等级：

    原来：gcc -O0 ...
    现在：gcc -O2 ...

-O0 基本不做编译器优化，适合调试和观察原始代码行为。
-O2 会让 GCC 自动对程序进行多种优化。

四、-O2 可能做了哪些优化

1. 寄存器分配
   尽量把频繁使用的变量放到寄存器中，减少内存读写。

2. 循环优化
   对循环结构进行优化，减少不必要的循环开销。

3. 指令调度
   调整指令执行顺序，让流水线更顺畅，减少等待。

4. 函数内联
   对一些小函数尝试内联，减少函数调用开销。

5. 冗余访存消除
   删除不必要的重复读取和写入。

6. 常量传播和表达式简化
   对可以提前确定的表达式进行简化。

五、为什么本阶段提升明显

当前 KF dense 矩阵代码中有大量循环和数组访问。
这些结构非常适合编译器做自动优化。

因此 -O2 的提升很明显：
    370.698124 ms -> 89.478562 ms

这说明在 ARM Linux 平台上，编译器优化是最基础、最重要的一步。
